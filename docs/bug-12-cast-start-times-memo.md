# BUG-12 仕様判断メモ: 席内ローテ時の castStartTimes 据え置き

**状況（2026-07-06 時点の実装）**: 席内ローテ（`rotateHosts`）は卓内の `currentHostIds` の並び順だけを回し、各キャストの着席開始時刻 `castStartTimes` は変更しない。そのため卓カード・卓詳細の「何分付いているか」はローテしても継続してカウントされる。

**論点**: 席内ローテの意味をどう扱うか。

- **A. 据え置き（現状）**: ローテ＝同一卓内の座席位置変更。卓に付いてからの通算時間が見えるので、「この卓に長く付いている人」を回す順番の采配判断に使える。回し履歴（sessionLog）も「卓を離れた時」に記録される現仕様と整合。
- **B. リセット**: ローテ＝接客の区切り。ローテごとに 0 分から数え直す。「今の相手に何分付いているか」は正確になるが、卓通算が見えなくなり、sessionLog にも「ローテを1接客として記録する」変更が必要になる。

**推奨**: A（現状維持）。理由: ①席内ローテは同一客グループ内の移動であり「客に付いている時間」は継続している ②B にすると Day10 までに固定したテスト（computeSetTimer / sessionLog）と挙動の意味が変わる ③現場の采配で欲しいのは「どの卓に誰が長く居るか」の方。

**B を採用する場合の実装ポイント**（ユーザーが B を選んだとき用）:
1. `rotateHosts` の tx 内で `castStartTimes` を全員 `now` に更新
2. 同時に旧区間を `sessionLog` へ追記（`removeCastPatch` と同じ形式・上限 30 共有）
3. `test/lib/seating-rotation.test.ts` に「ローテで開始時刻が更新される」ケースを追加

→ 最終判断はユーザー。判断があるまで現状（A）のまま。
